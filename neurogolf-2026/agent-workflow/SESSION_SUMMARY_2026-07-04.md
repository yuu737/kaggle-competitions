## 3. 主要な教訓(次回への申し送り)

1. **設計段階の gain_est は理論値**。実装後の実測は概ね理論値の 40〜50% に収束するか、
   構造的に逆転する(task029)。1 件ずつ実装→実測ゲートで判定し、合算を先に見込まない。
2. **机上 floor は最低でも ×1.4〜×3.3 の補正が必要**。特に「局所閉包」系
   (2×2/3×3 窓判定+パディング+膨張+code plane)は最低 4 段の中間テンソルを要し、
   1 段あたり 900〜3,600B が下限。
3. **既存 baseline は既に「単一 code plane→最終 broadcast Equal」パターンで
   高度に最適化されている**(例: task202 の 22 ノード/11,253B)。この既存パターンを
   上回るには、それと同等以上に段数を削る設計が必要で、単純な理論的書き換えでは
   不十分なことが多い。
4. **`[object, candidate]` 型のクロス照合構造(task233/044/077 系)は
   構造的に高コスト**。予算超過が疑われる場合は実装前に必ず費用概算を行う。
5. **GridSample 等、グラフ終端が無償の `output` テンソルに直結する既存構造を
   崩す書き換えは、理論設計が正しくても大幅な逆転リスクがある**(task029)。
