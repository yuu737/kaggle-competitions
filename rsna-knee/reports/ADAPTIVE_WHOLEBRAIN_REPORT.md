# 学習可能なMaleCNS全脳モデルへの改修

2026年10月9日。以前の固定ランダム入力＋固定回路＋出力層学習＋5%混合を見直し、MRI入力変換と全脳内部の神経タイプ別信号倍率も学習するモデルを実装した。全199,713状態・26,013,498有向接続を維持し、最終12出力は全脳の最終活動から作る。元モデル出力の直接混合はない。

保存済みの公開3検査では36予測中8個が1e-6以上変化し、最大差は0.016667。探索的58検査では696予測中649個が変化し、平均絶対差0.004169、最大差0.025862。『出力が同一』ではなかったが、精度への有効な貢献は確認できなかった。

## 改修した計算と学習

MRIの12,288次元の画像特徴 → 学習する64次元アダプター → 学習する神経タイプ別入力 → 全199,713状態で4段の有向伝播 → 全状態の神経タイプ別平均 → 学習する12出力。画像エンコーダは固定し、レポートは推論時に使わない。

細胞タイプ＋神経伝達物質で11,887群を作る。タイプ未付与のノードはsuperclass/class/side/NTで群分けする。群を共有するのは入力・信号倍率・読み出しであり、伝播中の神経状態や接続を小さな群グラフへ縮約していない。元の全ノード・全利用対象接続で計算する。

入力を `h0 = tanh(route(adapter(x)))` とし、各段で次を計算する。

```text
g_pre  = 0.5 + sigmoid(theta_pre[type])
g_post = 0.5 + sigmoid(theta_post[type])
m = g_post * A @ (g_pre * h)
m = m / sqrt(mean_over_all_nodes(m^2) + 1e-6)
h_next = 0.25*h + 0.75*tanh(m + 0.25*tanh(bias[type]))
```

`A`は既存の符号付きシナプス数を流入総数で正規化した行列。各接続の有効重みは `g_post[i] * A[i,j] * g_pre[j]` となる。ゲインは正で下限0.5があるため、元接続の支持集合と興奮・抑制の符号を保つ。グリア除外やNT符号の単純化など原データから失う情報は[既存仕様](docs/wholebrain_data_design.md)を引き継ぐ。

0.25の残留項は神経活動の持続であり、画像特徴を分類器へ直接渡す別経路ではない。ただし接続ゼロの介入でも初期活動の残留は残るため、「全活動を完全に消した」対照とは区別する。

教師信号は信頼度マスクと訓練部分だけで求めたクラス均衡重みを用いるsoft-target BCE。出力logitに対する勾配は `w*(sigmoid(logit)-target)/(batch_size*12)`。陽性はその異常の出力を上げる方向、陰性は下げる方向へ、全脳の時間展開を通じてアダプター・入力・内部ゲイン・出力を更新する。欠損項目は重み0で、教師値を変更しても損失が変わらないことを検証した。生物学的な餌・毒の報酬回路を再現した主張ではない。

設計の参考は[connectome制約下でタスク学習を行う視覚系モデルの研究](https://www.nature.com/articles/s41586-024-07939-3)。その研究の再現や、生理学的に検証済みの全脳シミュレーションではない。[PyTorch 2.10の疎行列仕様](https://docs.pytorch.org/docs/2.10/generated/torch.sparse.mm.html)に合わせ、固定CSRと転置CSRで活動への逆伝播を実装し、密行列の解析的勾配との差0を確認した。

## 比較条件

同じ4,278検査・同じ画像特徴・同じマスク付き弱ラベルを使用。UIDのSHA256により、訓練3,014・モデル選択618・最終比較646検査に固定分割。公式58検査はこれら全てから除外した。各方式8 epoch、最高dev macro AUCのcheckpointを採用し、全予定学習が終了するまで646検査のAUCを開かなかった。

実接続と行シャッフルは2初期値ずつ、迂回と通常MLPは1初期値ずつ。同じ学習ラベル・順序・損失・学習率設定・epoch上限を使用。迂回は同じ全脳モデルの行列演算を恒等写像に置換した同一パラメータ数の対照。通常MLPは同じ12,288特徴を入力する128→512→12分類器。旧固定全脳も新しい訓練分割のみで出力層を再学習し、以前の全件学習済みheadを持ち込まなかった。

元の公開CoAtNet headは補助的な参照値。弱ラベル検査ではK16、Gold58は既存K94予測なので、完全な公開0.950アンサンブルや同一窓数の全条件比較とは扱わない。

**646件もレポート由来の弱ラベルであり、臨床的な正解評価ではない。公開画像重みの来歴・弱ラベル生成の依存性も残る。Gold58は元画像モデル等の選択に使われたため、独立評価ではなく、今回のモデルや混合比の選択にも使っていない。**

## 資源と再実行

ローカルRTX A1000 6GBで全6条件の学習を17.08分で完了。学習時のPyTorchピーク割当VRAMは1.137GiB、OSピークRAMは1.983GiB。疎行列・活動・optimizer等を含むが、PyTorch以外のGPU使用量は含まない。今回の学習ではKaggle GPUを追加使用せず、MRIの再取得・再抽出も行っていない。

最小実MRI検証32件では1更新の中央値0.287秒。事前の全比較見積もりは約19分、訓練ループの上限は60分としてcheckpointを随時保存した。

```powershell
.venv/Scripts/python.exe scripts/train_wholebrain_adaptive.py smoke --out outputs/adaptive_reproduction --batch-size 32
# 新規出力ディレクトリを指定する。既存protocolへの無言の上書き・再学習は禁止。
.venv/Scripts/python.exe scripts/train_wholebrain_adaptive.py train --out outputs/adaptive_reproduction --epochs 8 --batch-size 32
.venv/Scripts/python.exe scripts/evaluate_wholebrain_adaptive.py --out outputs/adaptive_reproduction
```

新規出力先で再学習する前には同じ出力先でsmokeを実施する。推論は`scripts/infer_adaptive_wholebrain.py`で保存特徴またはMRIディレクトリを指定できる。`--data`の場合はtest.csvとMRIだけを読み、K16・2視点の同じ特徴を抽出して全脳モデルへ渡す。

KaggleのInternet無効推論用コード・学習済み係数・対応表をローカルに保存。Notebookは`notebooks/adaptive_wholebrain_inference/notebook.ipynb`、重み一式は`outputs/adaptive_wholebrain/model_bundle`。NotebookをKaggleで実行するには重み一式を私有入力として添付し、実際の入力参照をmetadataへ追加する必要がある。架空のデータセット参照は設定していない。新モデルのKaggle実行・大会スコアは未測定。比較で劣るモデルを改善版として提出しない。

## 推論の検証と今回の判断

同じ公開3検査の保存特徴で、学習・評価用GPU推論と独立したCPU推論CLIを比較し、checkpoint再ロード後の最大予測差は2.40e-07だった。36出力すべて有限値。これは同じ入力からのモデル実装の一致であり、Kaggleの非公開MRI推論を検証したものではない。

今回の実験フォルダーは約66.4MiB。初期基準からのワークスペース追加量は2.553GiBで、30GiB上限内。新規Kaggle GPU消費は0。

新推論はK16・2視点のみを使い、元アンサンブルのK94・補助ConvNeXtを実行しない。過去の4,339検査の特徴抽出1,899.4秒（うち61件にはK94も含む）から、1,300検査の画像抽出だけなら単純按分で約9.5分。全脳推論・起動・I/O・機種差を含む暫定計画値は約15分だが、新しい提出環境での全件実測ではない。公開3例の時間を全件へ外挿した値ではない。

**全脳に出力が依存し、その内部を教師信号で調整する実装は完成した。しかし、今回の条件で実コネクトームを使う性能上の利点は確認できず、採用できる改善とは判断しない。** 実接続2モデル平均の保留AUC0.95661はシャッフル0.96118、通常MLP0.96410を下回った。元の公開CoAtNet headの保留AUC0.96859にも及ばない。

次の検証候補は、集約済みのMRI特徴を各細胞タイプへ共通に入れる方法から、MRIの空間特徴を視覚回路の位置へ対応付ける入力へ変えること。現在の入力は同一タイプ内で位置による違いがなく、解剖学的な空間配線を活かしにくい可能性がある、という仮説による。付随情報に視覚座標のある23,720ノードを確認したが、それだけで適切なMRI入力対応が得られるとは限らない。新しい特徴抽出と対応の検証が必要で、改善はまだ実証していない。

今回の646件を見て次の設計を選ぶ場合、その後の同じ646件での比較は探索的と扱う。独立した性能確認には新しい評価データまたは別の検証設計が必要。
